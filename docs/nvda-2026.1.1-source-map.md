The complete source contains `source/synthDrivers`, `source/speech`, `source/globalPlugins`, `source/NVDAObjects`, `source/tests` support, and the full `tests/system`, `tests/unit`, and `tests/manual` trees. The current repository adapter reuses only the verified lifecycle/protocol boundary; it does not invent gesture injection or claim UI scenario success without a verified system-test bridge.

The official lifecycle is implemented by `tests/system/libraries/NvdaLib.py` and `SystemTestSpy/configManager.py`: it copies `nvda.ini`, installs the spy global plugin and spy synth under `scratchpad`, starts NVDA with `-c` and `--log-file`, connects a Robot Remote Server at loopback port 8270, waits for `NVDASpyLib.wait_for_NVDA_startup_to_complete`, and quits through `quit_NVDA` followed by profile teardown. `NVDASpyLib.emulateKeyPress` uses `KeyboardInputGesture.fromName`, `inputCore.manager.emulateGesture`, `queueHandler.eventQueue`, and watchdog sleep checks. Speech is captured by `speechSpySynthDriver.post_speech`; indexes and completion are handled by that driver. These components are suitable for a future thin bridge, but Robot Remote Server and the fixture application lifecycle are not currently installed by the project harness.
